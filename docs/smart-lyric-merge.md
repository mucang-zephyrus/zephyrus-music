# 智能翻译合并

原始解析结果保留在歌曲及歌词缓存中，`MusicHook` 使用 `normalizeLyricForDisplay` 生成显示歌词、秒级时间索引和合并记录。显示结果不写回缓存。官方翻译和罗马音在解析阶段先对齐；TTML 的结构化文本不参与推测。

算法版本为 `2.1.0`。处理顺序为句尾括号拆译、同行中英整理、整体结构分组、无时间文本分组、剩余同时间双行（50ms）。拉丁字母或汉字／假名占去空白字符至少 60% 才能参与识别。

跨时间分组从段首确定方向，允许 1–3 行原文后跟 1–3 行另一语言，每组起始时间跨度不超过 12 秒。空白、制作信息、未能可靠整理的混合文字、和声、已有官方翻译以及超过 12 秒的间隔形成边界。至少六组、两种语言覆盖率均达到 85%、最佳方向领先至少 10 个百分点才启用。双方独立逐字时间、原文词时间冲突、过长组和未配对尾句保持原样。全部同时间的双行由同时间规则处理，不能单独建立跨时间方向。

制作信息识别与隐藏制作信息功能共享完整角色匹配，覆盖鼓手、音频编辑、器乐/人声录音、录音棚及中英角色标签，不把任意冒号正文当制作信息。制作信息不进入合并覆盖率，智能整理不删除它们。

罗马音不再一律阻止跨行合并。原文的罗马音随原文按顺序保留；译文行只有空辅助字段或与该行文本完全相同的供应商回传才可消费。不同的辅助内容保持原样。同行罗马音只在能核对出相同完整英文后缀时拆分，否则跳过；括号规则仍保留对已有罗马音的保护。

无括号同行整理只推断“中文原文→完整英文后缀”。中文至少四字，英文至少八个字母、两个词，双方仍需满足 60% 字符占比。至少六条可安全拆分的同行候选，再结合从段首锚定的合法跨行组，要求双方解释覆盖率达到 85%、方向领先 10 个百分点。无法分类的正文也计入新规则的分母。不是遇到第一个英文字母就切开，原文内部的孤立字母保留；人名、外来词、短片段及无法确定词边界的行不拆。未加括号且两种语言均有独立逐字时间的行保持原样。已拆分同行不再作为拉丁行污染后续跨时间统计，跨时间六组门槛保持不变。

无时间文本使用独立门控，只整理 `startTime=-1` 的普通文本。合法相邻组与已确认的同行证据合计至少六组，双方解释覆盖率至少 85%，方向领先 10 个百分点。少量相邻组必须有足够同行证据，缺失时间不能当成同时发生。空行、制作信息及和声仍断段，文字表情仅在语言判断时作为注记，显示原文完整保留。输出仍为 `startTime=-1`、零时长、没有逐字信息，不生成时间戳，也不承诺同步滚动；有时间和无时间的证据不会互相放宽门槛。

这只能推断结构，不能验证两种语言的语义。三类规则实际改变歌词时，滚动区最后一句后提供反馈入口。提示不在歌词数组内，不参与索引、逐字动画、选择或字幕模式。反馈面板固定打开时的歌曲与来源；提交前可查看算法版本、规则和最多三组短片段，复用现有反馈接口，不自动发送或上传完整歌词。

“本首关闭智能合并”按歌曲平台／ID 与实际歌词来源标识在本设备保存。关闭只影响智能推测，官方辅助轨保留。播放器“控制 → 数据 → 歌词来源”可恢复自动处理。

缓存使用 schema 2。旧自动缓存过期并重新请求；旧手动选择不会被删除。能确定选择身份的网易云、社区来源可刷新；不能恢复原始歌词时保留旧快照并跳过全部智能规则，设置页明确显示此状态。

验证入口：`npm run test:lyrics`。`chunxiaoAlbum.test.ts` 使用专辑全部十首的时间、角色和辅助轨布局，正文和署名全部替换为合成文本，逐组断言来源索引、文本守恒、罗马音、恢复、幂等与时间索引。`mixedInlineMerge.test.ts` 覆盖同行门控及拒绝误合的情况。真实歌词快照只用于本机忽略目录验证，不存储进仓库。异步投影通过请求序号丢弃过时结果。
